# Project audit

Last reviewed: 2026-09-25

## Scope reviewed

The audit covered every tracked top-level area, all three native entry points,
build and release scripts, update paths, bundled assets, tests, licenses, Rust
dependency locks, generated artifacts, and repository hygiene.

## Changes made

- Removed Linux's bundled QSimpleUpdater and downloader. Bongo had disabled its
  downloader, so more than 1,900 lines and a third-party UI were compiled for a
  GitHub-page check that now uses Qt Network directly.
- Removed unreachable Linux tray code and stale declarations.
- Replaced deprecated screen geometry use with `QScreen`.
- Bounded and validated decompression of layout images, and removed unchecked
  manual allocations in the layout converter.
- Fixed the Linux settings build break caused by the stale `getCheckUpdate()`
  method name and fixed two Rust FFI ownership warnings.
- Added a Linux Cargo lockfile and made CMake use `cargo --locked`.
- Removed the generated `linux.json` update-feed workflow and its script. Linux
  now reads the official GitHub Releases API, matching macOS.
- Added GitHub CI for repository checks, the complete Linux DEB build, Linux
  engine tests, and macOS InputMethodKit integration tests.
- Removed the obsolete Windows timer, HTTP updater, and maintenance-only update
  script. The update command now opens the official GitHub Releases page.
- Hid Windows companion-tool commands when their executables are absent and
  removed the now-unused ICS networking dependency from the documented build.
- Updated visible legacy Windows branding while preserving file-format names,
  APIs, copyright headers, notices, and license text required for compatibility.
- Replaced the macOS sidebar's manual mouse-event control with native AppKit
  buttons and verified physical mouse navigation across Getting Started, Avro
  Layout, Settings and Fonts.
- Embedded the macOS input method inside the Applications app so the DMG exposes
  one Bongo app instead of a second installation bundle.
- Isolated generated installers under each platform's `release` directory and
  kept intermediate objects under ignored build directories.
- Made Linux user-data migration atomic and retained the legacy directory as a
  backup instead of recursively deleting it after conversion.

## Retained intentionally

- `vendor/rust` contains exactly the dependency name/version set in the macOS
  lockfile. Cargo checksum files cover the complete vendored packages, so
  pruning their upstream tests or metadata would break verification.
- Windows PCRE object files are linked by the Delphi implementation and cannot
  be regenerated by the documented Delphi-only build.
- Windows companion-project sources are referenced by the main UI. They are
  retained until the Windows product is either packaged with them or its menus
  are redesigned and tested on Windows.
- Upstream copyright headers, notices, and license files are required for the
  derivative code and remain outside the product UI.

## Known limitations

- The Windows target cannot be considered release-ready until its Delphi
  dependencies, runtime database/layout/skin payload, companion-tool decision,
  signing, and native behavior checks are complete.
- macOS public distribution still needs Developer ID signing and notarization.
- GitHub update checks require the repository and releases to be visible to end
  users. A private repository returns no release data to unauthenticated apps.
- Native packaging must still be tested on each release platform. CI cannot
  validate Delphi 2010 because that proprietary toolchain is not available on
  GitHub-hosted runners.
